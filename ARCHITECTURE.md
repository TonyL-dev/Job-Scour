# Architecture

Current experience editing (2026-10-15): Resume Studio's `ExperienceForm` writes company/title/start/end-or-present through the existing career service/repository API. On creation it stores entered summary/duties in the source description, then adds one referenced resume item per text. These are two explicit persistence steps: a library save followed by normal resume save/autosave. Source-detail edits preserve the existing description/metadata and refresh owned display facts in new resume versions; historical versions remain unchanged. Local source revisions also trigger autosave for detail edits affecting retained AI text. Resume-only text edits stay separate from library facts.

Resume Document v1 adds optional-on-input `experience_summary=false`; old snapshots require no rewrite or Alembic change. True is restricted to experience sections and conservatively limited to one sentence/one line/500 characters. Renderers emit a paragraph for the summary and bullets for duties in both HTML/PDF and semantic DOCX. Generation preserves the role and records invalid rewrites as unsupported; service-level revalidation covers internal review assignments. Existing source authorization, locks and privacy/cache invalidation remain in force. See README and the developer guides for current usage/contracts; historical phase entries below remain preserved.

For a current, source-linked onboarding explanation, start with [the developer handbook](docs/developer/README.md), [backend implementation](docs/developer/BACKEND.md) and [frontend implementation](docs/developer/FRONTEND.md). The entries below preserve the architectural history of each phase; early missing-feature statements describe their phase, not the final Phase 6 scope. Reusable project documentation is available in [the architecture template](docs/developer/PROJECT_ARCHITECTURE_TEMPLATE.md).

Updated 2026-10-07. Phases 0–5 implementation are present. The complete future design lives in docs/design/01-foundations.md. The foundation descriptions below are historical; the latest domain scope follows them.

## Runtime

React with Vite, strict TypeScript, React Router, and TanStack Query calls a generated OpenAPI client. The overview uses GET /api/health and presents connection, pending, and failure states; `/privacy` explains current scope. API traffic is same-origin through Vite in development and Nginx in Compose.

FastAPI uses Pydantic settings and response models. `app/health/router.py` delegates to its service, which obtains readiness through its repository. `app/core` owns engine/session configuration. The engine is created during lifespan and disposed on shutdown. Health queries the migrated users table; it does not initialize schema. `/api/health/live` is independent of readiness.

SQLAlchemy 2.0 supports SQLite and PostgreSQL/psycopg. Alembic revision 0001 creates the users identity foundation, with UUID ownership, timestamps, uniqueness, mode checks, and self-ownership. No users are auto-created, and no authentication endpoints exist. SQLite foreign keys are enabled per connection. Local SQL queries are confined to the health repository; migration code and tests operate on infrastructure deliberately.

Compose contains frontend, backend, PostgreSQL 17, and Redis 7. Migrations run before backend startup. Dependencies use health checks. Only frontend/backend ports bind to host loopback; PostgreSQL/Redis have persistent named volumes and no published host ports. The backend listens on its container interface, which is required for the frontend proxy, while host exposure remains loopback.

## Contract and quality

`scripts/export_openapi.py` exports a deterministic schema without connecting to a database. `openapi-typescript` generates frontend API types; `openapi-fetch` consumes those types. Both artifacts are checked in and checked for drift. `scripts/tasks.py` is the cross-platform task runner. A local pre-commit hook executes the check task. GitHub Actions runs lint/types/tests/build/audits and Docker smoke checks.

Dependencies are locked; generated assets contain no external fonts/scripts. The future domain call graph and Resume Document contract are design-only. There is no AI gateway, career CRUD, PDF renderer, background queue consumer, authentication, or encryption implementation in Phase 0.

The shared migration/model were exercised on native SQLite and PostgreSQL 18. Container PostgreSQL 17 and the Nginx runtime remain separate checks for the Compose CI job.

## Phase 1 domains

`auth/service.py` resolves a fixed local owner through its repository, initializing the identity on first use with concurrent initialization handling. Career/resume routes refuse server mode. All repositories scope queries to the resolved owner; client IDs cannot select another owner. Untrusted write origins are rejected and responses are no-store. This is loopback local identity, not server authentication.

`career` separates HTTP routes, typed validation/business services, and database queries. Twelve typed record kinds map to separate relational tables: experiences, achievements, projects, education, courses, skills, skill_evidence, certifications, volunteer_experiences, awards, publications, custom_entries. Alembic revision efdc4abcdd95 adds these plus resume_documents/resume_versions. Composite owner/parent foreign keys, parent XOR checks, enums, dates, importance, normalized skill uniqueness, evidence uniqueness, and indexes work on SQLite and PostgreSQL. All career rows can be retired; reads/retrieval exclude inactive ancestry without deleting referenced facts. Pydantic-derived form descriptions drive the category UI, including relationship dropdowns, metrics, and aliases. Custom entries currently use an inert string-to-string JSON details map.

`resumes` owns Resume Document schema v1, manual persistence, source validation, and render requests. Keys and references must be unique; AI items require sources at schema level, but Phase 1 write services accept only user content. References must exist, be active, belong to the local owner, and match the section/achievement parent. Display facts are reconstructed from stored sources, replacing caller-supplied facts. Style overrides are bounded presentation metadata. Header/contact details are user-confirmed snapshot data. Locks live only inside snapshots and are protection against future AI edits, not restrictions on manual changes.

Master metadata lives in resume_documents (title, master kind, latest version number, gold standard). The same transaction appends a full content snapshot and SHA-256 hash to resume_versions. Expected-version compare-and-update rejects stale saves; a partial unique index permits one gold standard per owner. Latest snapshot lookup uses the unique owner/document/version tuple rather than circular version pointers. No history/restore/duplicate UI exists yet. Existing snapshots and exports retain display facts after source retirement; new draft saves and previews require active sources.

`rendering` is a database-free leaf service. Classic and Modern are immutable built-in registry templates, not editable database templates. Both single-column layouts escape text, group consecutive matching fact headings, and render semantic headings/paragraphs. Allowlisted styles control A4 geometry. OFL-licensed Noto Sans/Serif fonts are embedded from checked-in assets. Chromium executes without template JavaScript or outbound requests; it awaits fonts, prints the exact HTML, and pypdf counts actual PDF pages. A semaphore bounds concurrent renders to two. Errors return an actionable 503; page targets warn without automatic fitting.

The default live preview draws the returned PDF itself using locally bundled PDF.js and its local worker. This gives exact PDF pagination without native browser PDF-viewer dependence. Canvas accessible labels include extracted text; a sandboxed continuous HTML alternative uses the identical HTML artifact. Debounced preview queries are removed from the cache when unused. Download renders the saved snapshot; save-and-download first persists the current draft. PDF response headers expose page count and HTML hash for parity checks. Fonts, Playwright/Chromium, PDF.js, and dependencies are pinned/checked in; no CDN is used at runtime.

At the end of Phase 1, embeddings/vector retrieval, LLM gateway, jobs, ATS scoring, importers, application tracking, server auth, encryption, autosave/history/restore, and fitting remained later phases. Phase 2 additions are described below. Docker installs Chromium dependencies and CI installs its test browser, but those runtime environments remain unverified locally.

`/docs` serves a local HTML API reference with an OpenAPI schema link. Default Swagger/ReDoc CDN assets are disabled so documentation also follows the no-CDN rule.

## Phase 2 domains

Alembic revision `171010dacb0f` adds owner-scoped llm_endpoints, model_profiles, task_model_assignments, prompt_versions, embeddings, job_descriptions, job_analyses, and match_analyses. Composite owner foreign keys protect configuration and job relationships. Enums, sampling bounds, and model budgets also have database constraints. Existing career tables and resume snapshots are preserved.

`settings` provides endpoint create/edit/disable, immutable profile creation, task assignments, and typed reads through router → service → repository. Endpoints canonicalize localhost to literal loopback; other destinations require explicit consent and HTTPS. URL credentials/query/fragment are refused. API keys reference backend `LLM_*` environment variables; key values are never persisted or returned. Local-mode ownership and origin checks cover the new routes.

`ai/gateway.py` is the only model-network boundary. HTTPX does not inherit proxy environment settings or follow redirects. Connectivity lists models, auto-detection probes only fixed loopback ports, and model tests validate chat JSON or embedding vectors. A per-app semaphore permits one inference at a time. Context budgeting uses a conservative UTF-8 byte estimate including schema, framing, and output reservation; it refuses rather than silently trimming input. This is not exact tokenizer measurement; the configured window must match the loaded server model. Structured modes are schema, JSON object, and prompt-only, with Pydantic validation and at most three attempts. Retries contain validation paths/types without echoing generated text. Requests have read and overall deadlines; cancellation closes HTTPX streams and releases the slot. Logs include model/timing/token-usage metadata when available, never prompt/response content. Endpoint updates invalidate stale configurations before subsequent outbound calls; an already transmitted request requires cancellation to stop it.

`ai/prompts.py` loads packaged JSON prompt files. Prompt snapshots are seeded idempotently per owner and never edited; their digests are recorded on analyses. Job text is JSON encoded as untrusted data, models have no tools, and every extracted requirement/keyword needs an exact evidence quote from that text. No Phase 2 service creates or changes career facts or resume content. Prompt-only output still passes the same schema and evidence checks.

`jobs` stores immutable pasted descriptions/metadata and append-only validated analyses. Cache fingerprints include the description, endpoint/profile configuration, rendered prompt, prompt digest, and output schema. Matching always runs against current active career data, even when job analysis is cached. Each match snapshot stores a career snapshot hash and owner-valid source IDs. The request-owned POST SSE pipeline emits stages, heartbeats, validated results, and sanitized errors. Disconnect/cancellation cancels its task; validated analyses and completed embedding-cache entries may remain reusable. This is not the durable generation-run/background-worker system scheduled for Phase 3.

`ai/retrieval.py` combines bounded cosine similarity, weighted keyword overlap, recency, and user importance for experiences, achievements, projects, and skills. Word boundaries and seeded/user skill aliases avoid Java/JavaScript and SQL/NoSQL collisions. Missing terms are based on lexical evidence, never inferred from similarity. Embeddings are JSON vectors with owner/entity/model/endpoint/content-hash cache keys, portable across SQLite/PostgreSQL; comparisons use deterministic Python rather than speculative vector-extension infrastructure. Matching without an assigned embedding model reports an explicit keyword-only warning; a configured failed embedding call produces an error. Editing text re-embeds it; retired sources and inactive ancestry never enter new matches. Similarity indicates relevance, not semantic truth or an ATS score. ANN indexes/fuzzy NLP adapters can be added if future performance requirements justify them.

React adds `/settings/ai` and `/jobs` through the generated client. Settings shows detection, profiles, assignments, connection tests, consent/disable controls, and a read-only prompt registry. Jobs shows saved descriptions, cancellable progress, evidence quotes, requirements, weighted keywords, coverage/gaps, and ranked sourced career records. The SSE reader handles split UTF-8 messages and premature disconnects. Privacy copy describes actual AI behavior. No CDN or telemetry is introduced.

The synthetic evaluation harness (`python scripts/tasks.py ai-eval ...`) uses ten paired career/job fixtures and the same AI extraction/quote-repair service as the product. It checks schema, quotes, required/preferred separation, stated/absent seniority/years, aliases/gaps, injection/fabrication traps, and repeated canonical required-skill stability. It does not read personal records. Prompt v1 is preserved and v2 is active, with explicit atomic-skill and exact-quote examples. Resume rewrite provenance, locks, fitting/page limits, and generation evaluation extend this harness in Phase 3. ATS/tracker/history/privacy controls remain Phase 4; Docker/hosted runtime checks remain separate.

Repositories return detached analysis DTOs rather than ORM rows to business services, keeping lazy database reads inside repositories even when matching refreshes its session. A second active-career snapshot check refuses results if sources change during embedding work; completed validated analysis/vector entries can still be reused on retry.

Extraction 2.1 deterministically recognizes narrowly defined leading seniority titles and explicit required/minimum-experience declarations, preserving exact posting quotes. It does not infer level from generic titles, senior-citizen references, or company age. Its version is included in cache fingerprints. Model test routing is service logic. The evaluation grader compares stated numeric years separately from programming-language token boundaries, so `5+ years` remains valid while C/C++ and Java/JavaScript collisions are rejected.

Current validation: the final ordinary suite (17 backend/12 frontend tests), Python 3.12, and PostgreSQL 18 schema/domain checks pass. Real local Qwen2.5/Devstral runs, retests, final-output replay, and Nomic vector/browser checks are distinguished in IMPLEMENTATION_STATUS.md. LM Studio's Nomic loader failure was bypassed only for validation with its existing CPU embedding server; it was not repaired by product code. Temporary services are stopped after testing. Docker and hosted CI remain separate, unverified environments.


## Phase 3 generation and review — 2026-10-07

Alembic revision `3fa6b17e6fda` adds generation_runs and generation_suggestions with composite owner foreign keys, status/review-revision constraints, immutable input/base snapshots, checkpointed proposals, append-only suggestion records with an active suggestion list, persisted decisions/locks, progress timestamps, model/prompt provenance, and a link to the saved tailored document. Resume kinds now include tailored, and model assignments include ranking/rewriting/summary/verification/condensing. SQLite batch migrations temporarily disable foreign-key enforcement outside the transaction and check the entire graph afterward; existing masters/versions remain intact. A lossy downgrade with tailored documents is refused.

`resumes/generation_router.py` adapts HTTP only. `generation_service.py` owns orchestration, review assembly, scopes, locks, fitting, and a one-worker/four-outstanding-task local queue. Repositories exclusively query the database and return detached DTOs. Each worker owns a separate session. Browser disconnection closes only SSE; persisted runs and GET/event replay permit reconnecting. Explicit cancellation closes model requests and preserves completed checkpoints. Startup marks interrupted queued/running runs failed with retry guidance instead of pretending an in-memory worker can resume. This local runtime supports one backend process; server mode remains guarded.

The pipeline reuses job analysis/current evidence retrieval, supplies at most 24 short candidates for model ranking, applies a template/page-derived initial item budget, rewrites unlocked sourced items separately, copies skills from the stored library, orders skills by relevance without moving protected positions, then writes summary from selected evidence. `ai/generation.py` alone invokes the existing gateway for generation tasks. File-seeded immutable prompts keep guardrails separate from user instructions. HTTP verifier sampling is forced to temperature zero; Codex manages its sampling. Every AI rewrite needs supplied owner-valid IDs, matching numbers, cited technology/alias evidence, and conservative source vocabulary; a second model call labels semantic support. Unsupported/partial proposals stay visible and excluded from the generated draft and default review. Unsourced manual content is preserved with a warning, not passed off as verified AI content.

Actual PDFs drive page fitting. Ordered steps remove low-relevance unlocked bullets, remove lower-relevance older fact groups, ask the condensing model to preserve metrics, then optionally adjust bounded spacing/font size when consent was provided. The original template/header/structure are preserved; layout permission is explicit. Remaining protected overflow is reported, and fewer than 200 extracted characters on a final page triggers an orphan-inspection warning. This is a transparent text-density heuristic, not a claim of exact geometric fill.

Review assembles only the user's chosen item/order suggestions. Unsupported AI output cannot be accepted directly; manual edits have user origin and still require active valid references. Preview and commit recheck career snapshot/source text and hydrate employer/title/date facts from stored records. Review decisions and the new tailored snapshot commit atomically under a revision compare-and-update. Repeated commit returns the same saved document. Later review changes do not mutate that snapshot. The run retains its base and output lineage; history/restore/autosave and ATS reports remain Phase 4.

React `/generate` exposes saved runs, SSE with polling fallback, side-by-side original/proposed text, verifier reasons/source evidence, accept/reject/edit, review persistence, future-regeneration locks, item/section scopes, presets/free-text instructions, debounced actual PDF.js preview/page counts, and a separate tailored save/download. Master-resume editing lists only masters. All assets remain local and no telemetry is added.

Final generation context is named factual JSON (`facts.v1`), excluding ranking/review weights and UUID/date metadata. Stored achievement metrics also have an exact normalized value/unit statement. Claim checks 3.2 distinguish negative signs and percentages and avoid precision loss. V3 verification explicitly recognizes associated structured metric/degree fields as evidence; v1/v2 remain preserved. Older-run acceptance rechecks current claim rules, while historical exports remain unchanged. Visible protected/non-retrieval records can support summaries; hidden records cannot populate summary context.

## Phase 4: ATS, immutable history, tracker and privacy — 2026-10-07

Alembic `20d2f08208c7` adds ats_reports, applications and application_events with composite owner/version/job references, stage/revision constraints, and indexes. Resume versions acquire an owner/id unique key, change kind and restored-from reference; documents retain parent lineage. Generation runs retain an exact saved-version FK (older committed runs backfill version 1). The migration preserves existing content snapshots. A downgrade refuses to discard populated ATS/tracker tables.

`ats` owns deterministic analysis through HTTP adaptation → service → repository. Reports persist engine `ats.1`, exact version/optional saved analysis, measured PDF pages, weighted coverage/subscores, matched/missing terms and prioritized linked findings. Shared lexical normalization/seeded and career skill aliases avoid Java/JavaScript collisions. Missing terms distinguish available career evidence from gaps; related technologies remain missing and get a partial-coverage note. The engine checks action verbs, metric availability, long/passive bullets, keyword repetition/density, expected section types/chronology and bounded heuristics. Actual Chromium output is parsed with pypdf and checked against ordered visible HTML text, including contacts, facts and dates. Reports never invoke a model or alter content. Report snapshots reflect career evidence at creation; rerun after edits. Scores/readability/sparse pages are guidance, not vendor compatibility or semantic truth guarantees.

`resumes` adds owner-scoped version reads/exports, comparison UI, restore/duplicate, explicit lineage and change origins. Restore appends the historical snapshot; duplicate creates a separate document. Both preserve historical facts, even retired references. New manual edits still hydrate active facts. Master and tailored documents share the editor; text changes become user-origin content. AI-origin items must match an existing saved item, then pass current claim checks before preview/save. Generation review remains the only path for new AI claims. New saves use revision CAS; unchanged saves do not create extra versions. Autosave waits 1.8 seconds after valid edits, preserves edits made during an in-flight request, and stops on conflict. Saved-generation downloads and commit replay use the recorded version, so later manual edits do not change the run's original snapshot.

`applications` stores exact version/job links, company/role, dates/source/notes, follow-up state and revision. Initial stages and changes append events atomically; explicit dated events are also available. Queries return detached DTOs including document/version identity. The table/board UI supplies filtering, due follow-ups and recorded response-stage counts by exact version. It does not contact employers or schedule external reminders.

`privacy` separates HTTP cookie/download handling, security/data-control services, and queries. Local passcodes use random-salt scrypt; process-local session tokens are random, HttpOnly, SameSite=Strict and expire after 30 minutes. Browser inactivity locks at 15 minutes; startup locks when a passcode exists. Unlock failures have bounded exponential delays. The middleware rejects locked private routes, withholds responses from revoked requests, and disables all privacy features in server mode. `core/workspace.py` binds sessions to a revocable epoch, guards reads/flushes/commits, serializes commit-versus-invalidation, and stops older SSE readers. Lock/delete cancels generation; deletion blocks new operations and prevents pending analysis/embedding writes from restoring removed data. Session infrastructure owns these guards, while repositories alone query tables.

Full JSON export includes retired records and all owner tables except local identity/password hashes. ZIP export adds actual PDFs for every version. Delete-all removes the owner graph in reverse dependency order, including caches/settings/prompt snapshots/embeddings/ATS/tracker, retaining identity/passcode. SQLite secure_delete is enabled. Existing exports/backups and provider-side data are independent and cannot be erased by this control.

`core/cipher_database.py` configures optional SQLCipher for file SQLite using APP_DATABASE_PASSPHRASE, an Argon2id-derived 32-byte key and 16-byte .salt sidecar (64 MiB, three iterations, four lanes). The offline copier refuses overwrites, verifies integrity/foreign keys and leaves plaintext source files intact. Startup and Alembic use the same configured engine. SQLCipher protects all database columns; the current Windows wheel's optional memory-security pragma is omitted after a native stack-overflow failure, without claiming memory protection.

`core/encryption.py` adds optional typed AES-GCM envelopes for descriptive Text and JSON columns, using fresh nonces and column-bound authenticated context. A keyed HMAC index preserves skill equality/uniqueness. Relational dates/numbers/IDs/status/configuration indexes remain queryable; PostgreSQL volume encryption remains an operator responsibility. APP_ENCRYPTION_KEY is backend-only and never exported. Offline field conversion uses reflected raw columns in one transaction, preserves semantic hashes, validates existing ciphertext and vacuums SQLite. Startup checks protected fields before serving and disposes failed engines. Missing/wrong keys, tampering and unconverted protected plaintext fail closed. No key recovery/rotation or plaintext-backup erasure is claimed.

React adds /history, /applications and operational /privacy, a lock gate that fails closed when status is unavailable, and current-editor links. Queries are cleared on revocation and lock state is checked again before showing content. All assets remain local. Dedicated Playwright scripts use a separate test-only synthetic gateway/server, temporary encrypted stores and loopback services; product entry points never load those fixtures.

## Phase 5 hardening and installation — 2026-10-07

Rendering keeps a process-local LRU keyed by the full escaped HTML hash. Validity is 60 seconds; count/payload caps are eight entries/24 MiB. Expiry is checked on access; privacy events and app lifecycle clear entries and advance an epoch, preventing late insertion from renders that began before revocation. The existing database-free renderer still limits Chromium to two jobs, with a five-second admission timeout. Active-source validation occurs before rendering; historical versions continue to render stored facts. This single-workspace cache is not an authenticated multi-owner server design.

The ai gateway bounds active plus waiting inference requests to five, allows one inference, and expires admission after 30 seconds. Its async context manager releases capacity on success/failure/cancellation. Existing generation queue, provider consent, subprocess isolation and structured/evidence checks remain unchanged.

core/http.py is shared ASGI infrastructure: it bounds write bodies to 4 MiB before JSON parsing, including chunked input, and applies no-store/nosniff/no-referrer/no-framing headers to handled responses. Nginx matches the write limit, disables SSE proxy buffering and serves a restrictive production CSP. Vite preview has equivalent production headers and same-origin proxy for release checks. No new API schema or database migration is required.

React adds a route recovery boundary without displaying exception text, a skip link, route focus/title updates, keyboard-focusable PDF/table/board regions, PDF drawing status, improved text contrast and reduced-motion handling. Missing libraries and jobs/runs/versions have retry/pending/empty guidance. The privacy gate clears private queries when polling detects a lock as well as on explicit revocation.

The task runner checks Python/Node/pnpm versions before setup and provides doctor/fresh-install. Doctor reads readiness/storage validity and renders synthetic content only. fresh-install copies explicitly named source files, creates fresh dependencies/database, follows README commands, builds the production UI and tests keyboard/manual save/PDF/ATS/outage/restart persistence with no model calls. ### Phase 6 final architecture — 2026-10-08

The implemented dependency and lifecycle design is [docs/design/06-enhancements.md](docs/design/06-enhancements.md). Five separate domains now own import review, profile questions/confirmation, cover letters, prompt preferences/evaluations and custom templates. Alembic revisions 601a_imports through 606f_templates extend the schema without rewriting historical documents. Existing built-in template IDs remain valid. Routers adapt HTTP, services enforce business rules, and repositories return detached owner-scoped values; only ai performs inference.

Imports persist parsing/review/failure state, use isolated bounded subprocesses and commit approved parent graphs atomically through career services. Originals remain in memory by default; explicit retention and all PNG assets require owner-bound AES-GCM ciphertext in the database. Startup registers the complete model catalogue and verifies ciphertext/key availability, including these mandatory private files. Cancellation registers children behind the workspace barrier and prevents late results.

Profile confirmation records user-supplied answers and compares the captured career revision before writing. Letters use a captured job analysis, selected evidence, conservative checks and separate semantic verification, then immutable independent versions. Applications may reference an exact submitted letter version. Current source/ancestor guards hold through acceptance; historical exports use stored facts. Local cancellation, restart recovery and workspace epochs apply to new operations and export/delete covers their complete graphs.

Prompt customization exposes immutable supported tone/focus preferences. Packaged guardrails, schemas and source authority remain fixed. Three synthetic cases compare captured baseline/candidate configurations; activation requires a passing matching report, unchanged provider/verifier/base configuration and an expected-active check. New cache/provenance fingerprints include the custom digest. The explicit Codex setup action now assigns nine chat tasks; existing settings are never silently assigned. Codex sampling remains provider-managed.

Custom revisions embed validated presentation and encrypted asset copies into Resume Document v1. Save/preview uses actual synthetic Chromium PDFs and records extraction/order/heading/contrast/page findings; document ATS remains a separate heuristic assessment. Full HTML/asset hashes feed the existing private render cache. DOCX is a bounded database-free OOXML exporter with semantic headings/bullets/links and bundled embedded Noto fonts.
