# Phase 5 security review — 2026-10-07

Scope: PROJECT.md section 8 against the local MVP, including Codex steering and the existing Phase 4 storage controls. This is a source review and regression validation, not an independent penetration test. Final executed checks are recorded in IMPLEMENTATION_STATUS.md.

| Section 8 control | Implemented boundary / evidence | Limits |
|---|---|---|
| Local by default / remote consent | Loopback native binds, loopback published Compose ports, trusted hosts, explicit endpoint consent, HTTPS for non-loopback HTTP providers; fixed Codex provider marker. Model requests remain in ai. | Codex is remote and requires consent; LAN addresses are treated as remote. A configured operator can change host binding; never expose local mode to a network. |
| Encryption at rest | Optional SQLCipher with Argon2id storage key and salt; optional AES-GCM descriptive fields and blind skill index, fail-closed startup tests. Secrets stay backend-only and are stripped from model children. | Passcode and storage passphrase differ. Field-only encryption leaves metadata queryable; PostgreSQL volume protection is operator-managed. No automatic conversion, key recovery, memory hardening or key rotation. |
| Uploads / import parsing | No upload/import route, parser or stored upload feature in this MVP. | Future importers must add content-based validation, bounded sandboxing, encrypted storage and authenticated access before shipping. |
| Telemetry / third-party assets | Bundled fonts/PDF.js; templates block scripts/network; no telemetry exporters; browser checks reject external asset requests. | Package installation/audits and explicitly consented providers use the network. Provider logging/retention is external policy. |
| Logs | Application inference logs contain metadata only; CLI diagnostics/output bounded and suppressed; SQL engines hide parameters. | Operators must protect runtime logs; metadata/URLs may still be sensitive. No opt-in prompt logging or expiring-log feature is offered. |
| Export / delete / backups | JSON and JSON/PDF ZIP export; owner graph deletion, generation cancellation, epoch barrier, stale-analysis/commit/SSE regressions. Phase 5 invalidates private render caches, including late fills. | No uploaded data exists. Downloads, provider copies and backups are not erased. Encrypted automatic backup/import is a future enhancement. |
| Local passcode / abuse limits | HttpOnly SameSite cookies, bounded failed unlocks, session/restart/inactivity locks, owner checks, origin rejection. 4 MiB ingress bound applies before JSON parsing, including chunked writes. AI pending queue and render admission are bounded. | Trusted local OS is the security boundary. Loopback-only apps do not authenticate all same-machine processes. No server login/CSRF/TOTP implementation is claimed. |
| Server authentication / authorization | Server domain guard retained; repository owner scoping/composite keys tested. | This release is single-owner/local; no multi-user or distributed worker deployment is supported. |
| Templates / XSS / PDF safety | Immutable built-in escaped templates, allowlisted styles/URLs, offline no-JS Chromium; React escapes model text; sandboxed HTML preview. Production CSP/nosniff/no-referrer/no-framing; API no-store headers. | Built-in PDF output is trusted generated input; arbitrary uploaded PDFs/custom templates are not accepted. Inline styles are required by rendering; CSP permits those styles but not inline scripts. |
| Prompt injection / factual output | Job data delimited; schema validation, no model tools/actions, source/number/claim checks, separate verification and current-source recheck before save. Codex subprocess isolation controls preserved. | Semantic verification can reject valid paraphrases or miss arbitrary unsupported claims; review is required. Queue hardening changes no prompt or claim policies. |

The render cache is process-local for one workspace: SHA-256 of the complete escaped template output, at most eight entries and 24 MiB of payload, 60 seconds validity, no disk persistence. Expired entries are purged at the next lookup. Lock/change/delete/shutdown advances an invalidation epoch so an already-running render cannot reinsert revoked data. This cache does not bypass active-source validation or database workspace epochs. Multiple owners/processes must use scoped caches in a future authenticated-server design.

Release tests use disposable synthetic stores and explicit source allowlists. No personal store or credentials are copied to installation fixtures. Dependency audits contact advisory services and are recorded separately from runtime privacy. Fresh environment, Docker, hosted CI and live model evidence must each be labeled accurately; a passing synthetic provider is not account-backed compatibility or proof of semantic truth.

Container build contexts now use explicit source allowlists; dependencies, environment files, personal stores/salts and validation output stay outside them. Nginx explicitly serves the PDF.js .mjs worker as JavaScript, with UTF-8 and production CSP. A real container browser test caught the previous octet-stream MIME failure; final actual PDF.js/HTML rendering, retry, passcode and CSP checks passed after the fix. API proxy errors also receive no-store headers.
## Phase 6 extension review - 2026-10-08

The preceding Phase 5 table is historical. Phase 6 now accepts reviewed uploads and bounded custom presentation. Local single-owner/server guards, provider consent, source checks, immutable versions, API privacy headers, source-only build contexts and workspace epochs remain enforced.

| Area | Implemented controls and evidence | Residual scope |
| --- | --- | --- |
| Imported documents | 2 MiB signature/MIME/extension validation; isolated Python worker with minimal environment, two admissions and a 15-second deadline; 30 PDF pages, 256 DOCX members/8 MiB expansion, 200,000 characters/500 fragments. No archive extraction, external relationship fetch, script/macro execution or XML entities. PDF actions and active DOCX content are refused. Persistent parsing/failure states, kill-on-cancel and restart recovery prevent unfinished results appearing complete. | Not an OS memory sandbox or universal document parser. OCR, password-protected and unsupported documents are refused. Peak library memory before the deadline is not certified; overloaded-host timeouts are explicit errors. |

Owner/UUID AAD, generated storage identity, startup key/tamper checks, private download/delete and encrypted export envelopes. | Key loss prevents recovery. Extracted text/metadata still require the existing optional field/full-store encryption for at-rest confidentiality. Downloads/backups/provider copies are independent. No automatic key rotation/recovery or memory hardening is claimed. |
| Staged career writes | Exact excerpts/locators, closed model staging schema, literal fact/metric checks, user review, duplicate hints, active owner-valid parents, atomic graph commit/revision CAS and idempotent replay.
